# 2026-10-25

## 修复 VSCode 模式「无故删除所有文件 + 盲打 + 定位失败」

根因（modes.py::VSCodeMode.before_type）：
- 615-624 行对目标文件做磁盘截断（open(abs_path, "w")）后才判断 is_empty，
  导致键盘清空分支成为死代码；编辑器缓冲不受影响，磁盘/文档双写错位；
  F10 中断留下空文件。
- 定位器（code --goto / Quick Open）结果零验证，失败静默继续打字，
  Ctrl+A/Delete/Ctrl+S 作用在错误文档上。
- 测试盲区：sanity_check 的 before_type 测试用无 abs_path 的 Target，
  且 test_vscode_keyboard_rel_to_workspace 把磁盘截断断言成规范。

修复：
- 删除磁盘截断，清空改为守卫通过后无条件 Ctrl+A+Delete（编辑器内）。
- 新增 modes._foreground_window_title + VSCodeMode._verify_target_window：
  定位后校验前台窗口标题含目标文件名与工作区/目标目录名；失败抛
  RuntimeError → acquire_failed → 该文件 FAIL 跳过，零破坏性按键。
- VSCodeLinuxMode.before_type 改为先激活窗口再走基类。
- 测试：改造 4 个既有测试（补 abs_path/check_window/伪造前台标题），
  新增 guard_blocks_on_wrong_window，反转把 bug 当规范的断言。
- README 补充定位守卫说明。

验证：sanity_check 42 PASS、validate ALL VALIDATION PASSED、
_repro_before_type.py 三场景 PASS（磁盘字节不变、守卫失败零键）。

附带发现（未修，范围外）：test_pause_blocks_typing_and_resumes 是既有
flaky（8 次跑 1 次失败，_send 检查 paused 与 type_char 之间的竞态）。
