# 2026-09-23 — GUI 去掉"演练测试"环节

## 需求（用户原话）

「把演练测试环节删除，改为用户点击按钮后直接开始倒计时并进入正式流程。」

## 改动（只动 GUI 与文档，CLI 的 dry-run 保留）

- `gui.py` 删除 `btn_dry`（「① 演练测试（不动键盘）」）与一切演练分支：
  `_start()` 不再收 `dry_run` 参数，`_collect_config()` 固定 `dry_run=False`
  且去掉 `extra_speed`（原来演练靠 ×20 加速），去掉了 `sched.threshold = 1e18`。
- `_countdown(typer, n)` / `_launch_worker(typer)` 不再带 `dry_run`；队列消息从
  `("done", (dry, s))` 简化为 `("done", s)`，日志行去掉 `[演练/实机]` 前缀。
- 按钮文案改为「▶ 开始真实输入」，警告文案改成"点按钮后就是倒计时，请在这几秒内
  把光标点进目标窗口"。
- 结束后状态分三种：已停止 / 完成 ✓ 内容一致 / 结束但内容与源文本不一致（看日志）
  —— 这是原来演练按钮给出的"内容一致"判定的替代。
- `selftest()` 里**不能**再跑真实输入，改为：断言 `_collect_config().dry_run is False`、
  向队列注入 `("done", s)` / `("error", tb)` 验证界面复位与状态文案、用本地
  `FakeTyper` 验证倒计时编排（n>0 只排 after，n<=0 才进工作线程）。
- `README.md`：GUI 使用流程改写（点按钮 → 倒计时内切窗口）；安全清单第 1 条补上
  「GUI 没有 `--window` 校验」、第 5 条把速度倍率的说法改成 GUI/CLI 两用。

## 验证

- `py gui.py --selftest` → GUI SELFTEST PASSED（无 stderr 噪音）。
- `py sanity_check.py` → 15 项 PASS + ALL SANITY CHECKS PASSED。
- `py validate.py` → BATCH PASS + KILL-SWITCH PATH OK + ALL VALIDATION PASSED。
- `py main.py --file source.txt --seed 3 --speed 300` → 真实 5036 字符源文本
  `final_matches_source: True`、consumed 5036/5036。

## 注意

- CLI 的 `--live`（默认 dry-run）**故意没动**：那是命令行默认值，不是"演练环节"，
  去掉会让 `py main.py` 默认直接往当前焦点窗口灌字。README 里已写明"想空跑验证文本
  模型用 CLI 的 dry-run"。
- `py main.py` 不带 `--speed` 时是 1.0 倍速：5036 字符 ≈ 9 分钟，命令行冒烟测试务必
  加 `--speed`（本次我因此撞过一次 2 分钟命令超时被杀）。
