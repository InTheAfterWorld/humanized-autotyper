## 多文件切换异常：光标残留 + 非空目标

用一个带真实文档模型的假编辑器（_repro_switch.py）复现，四个场景：
- A 干净目录/顺序 -> 内容正确
- B 干净目录/交替（每 5 字符）-> 内容正确
- C 目标文件已有旧内容 -> 新内容插在旧内容**前面**，长度不符 FAIL
- D 首次打开光标不在 0 -> 空文档下退化为追加，未暴露；非空时即 C

根因：
1. before_type 首次打开时默认光标在 0。VS Code 会为每个文件记住上次光标
   位置，--goto 与 Quick Open 都恢复它；不复位就把新文本插进旧内容中间。
2. 删掉清空动作后，目标文件非空时必然得到「新+旧」，且要到 after_type
   才报一句模糊的长度不符。

修复（最小化）：
- executor.key_doc_start()：Ctrl+Home，与 key_doc_end 对称。
- VSCodeMode.before_type 首次打开、打字前调 key_doc_start。
- preflight 新增：目标文件已存在且非空 -> 阻断并列出文件名。
- 测试桩补 key_doc_start；README 补两段说明。

验证：sanity 42 PASS、validate PASSED、_verify_linux_guard 4/4、
_verify_preflight_linux 4/4、_repro_switch A/B/C/D 全部 PASS。

未验证：真实 VS Code 下 files.insertFinalNewline 与集成终端聚焦的影响；
同名不同目录文件在守卫里仍只按 basename 比对。

## 关键发现：用户的测试终端是无 DISPLAY 的容器

用户在 /workspaces/TerminalCraft 里跑 xdotool，报
`Error: Can't open display: (null)`。这不是切换失败，是环境里没有 X 服务器：
- xdotool 无法读标题 -> preflight 拒绝真实输入（按设计）
- pynput 的 X11 后端在 import 期连 display（executor.py:197-201 无 try/except）
  -> 预期直接抛 DisplayNameError，Executor 构造不出来，一个键都发不出
- code --reuse-window 在容器里连的是 VS Code Server，不存在前台窗口概念

用户确认：真正的目标是一台**有桌面的 Ubuntu**（X11 会话），容器输出无效。

新增 _probe_switch_linux.py（只读，不注入按键）：检查会话类型/依赖、
读标题、跑一次 code --reuse-window --goto 再读标题、按守卫判据
（文件名 + 目录名）给结论，并打印 wmctrl -lx 的 WM_CLASS。
退出码 0=守卫会通过 1=会拒绝 3=环境不成立。
Windows 上试跑已正确识别无 DISPLAY 并退出 3。

仍未验证：Ubuntu 桌面上 code --goto 的前台行为、标题格式、
WM_CLASS 是否为 code。等用户回传探测输出。
