# 2026-09-22 — Humanized Autotyper：bug 审查与修复

## 做了什么

通读 12 个模块，修掉 12 处缺陷（详见当日回复），其中两处是会真实损坏数据的：

- **GUI「开始真实输入」从未真正输入**：`_collect_config` 把 `Config(dry_run=True)`
  写死，`_start(False)` 只改了 `extra_speed`，于是实机按钮一直空跑演练。
  现在 `dry_run` 由 `_start` 传进来，selftest 加了断言。
- **停止时正在"删了还没补打"的片段会永久丢字**（EDIT_PREVIOUS / REWRITE_CHUNK /
  BACKSPACE_BURST）：原实现在重打循环里 `if kill: break`，删除已经落键、补打被放弃。
  改为「删除前才检查 kill；一旦开始删，就用 urgent 节奏（`Config.urgent_hold=0.008`）
  把这段打完」——停止延迟被限制在这一个片段内，文档不再缺字。

- 现有测试可能是**靠 bug 通过的**：`test_burst_unit` 依赖"行首 cap=1 时也计一次爆发"
  这个假计数才通过（DEMO_SOURCE 第 500 字符正好在行首、列号 1），修掉计数后它立刻失败。
  改动计数器时先怀疑测试。
- 项目已装 pynput（win32 后端）：CJK 走 `KEYBDINPUT.UNICODE` 注入；
  emoji（>0xFFFF）由 pynput 自己拆成两个 UTF-16 单元；`"\r"` 会被映射成**真的 Return 键**，
  必须归一成 `\n`；`"İ".lower()` 是两个码位，会让 `KeyCode.from_char` 抛 TypeError。
- 编辑 `/^\s*if ` 这类短串时容易被匹配到 `elif` 的尾巴而把 `el` 留下（本次踩过一次），
  改完务必 `py_compile` + `difflib` diff 复核。
