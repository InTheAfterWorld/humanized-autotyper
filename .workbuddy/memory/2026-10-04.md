# 2026-10-04 — 行为保真度增强：二元节奏 / 错误率耦合速度 / 回读遍数

## 需求

用户在代码审查后要求「实现方案 1、2、8」，即：
1. **二元节奏（同指代价）** —— 相邻两键的手指关系决定延迟
2. **错误率与局部速度耦合** —— 打得越快越容易出错
3. **回读遍数（review_passes）** —— 写完一行偶尔回扫一眼刚写的内容（只读）

## 改动（4 个源码文件 + 测试 + 文档）

### 1. 二元节奏

- `keymap.py` 新增 `FINGER`：标准触键指法表（手, 指），26 字母全覆盖。
  注意**字母行是每指一竖列**（`qaz`/`wsx`/`edc`…），所以 `w` 与 `s` 是**同指**，
  不是"相邻键"——这点很容易搞错。
- `keymap.py` 新增 `dyad_factor(prev, cur, same_finger, alt_hand)`：
  同指返回 `same_finger`(1.35)、双手交替返回 `alt_hand`(0.85)、
  同手异指返回 `1.0`、同键/非字母返回 `None`（不参与）。
- `delays.py::sample` 在上下文因子之后、疲劳之前乘上该因子。
  **突发段只保留三成幅度**（`0.3 if bursting`）——burst 代表肌肉记忆自动挡，
  手指差异被抹平，这与原有的 `sigma *= 0.5` 同源。
- `config.py` 新增 `dyad_same_finger=1.35`、`dyad_alt_hand=0.85`；都设 1.0 即关闭。

### 2. 错误率耦合并局部速度

- `delays.py` 新增实例属性 `tempo_factor`：记录**最近一次 sample() 的局部速度因子**，
  刻意排除疲劳与预热这类慢变量（它们不该改变正确率）。
- `typos.py::roll` 新增 `tempo_factor=1.0` 参数，实际概率
  `p *= tempo_factor ** (-typo_speed_exponent)`，并 `min(1.0, p)` 兜底。
- `machine.py::_emit_intended` 调用时传 `tempo_factor=self.delays.tempo_factor`。
- `config.py` 新增 `typo_speed_exponent=1.2`。
- **默认参数下 tempo_factor 恒为 1.0**，所以 `sanity_check.test_typos` 的
  `te.roll("d", ...)` 行为完全不变（速率仍是 1.2%）。

### 3. 回读遍数

- `machine.py` 新增第 7 个状态 `REVIEW` 与 `_h_review`：
  `_navigate_to(cursor - back)` → 停顿 0.25–0.9s → 再左移 1–3 格（视线微动）
  → 停顿 0.15–0.5s → `_return_to_end()` → 停顿 0.1–0.35s。
  **只移动光标、不删不打**，所以 `buffer.text == source` 不变式完全不受影响。
- 行尾抽签表里加入 `("REVIEW", p_review)`，排在 REWRITE_CHUNK 之后。
- `config.py` 新增 `p_review=0.02`、`review_back_range=(5, 25)`。
- `stats` 新增 `reviews` 计数；CLI 的 summary 会自动打印（它遍历所有 key），
  `gui.py` 的输出行加了 `reviews={s['reviews']}`。

## （第二轮）失焦暂停 / 恢复 + 暂停按钮 + 状态栏 ETA

### 需求

「实现失焦暂停 / 恢复 + 「⏸ 暂停」按钮，状态栏补 ETA + 当前状态」。

### 改动（machine.py / executor.py / gui.py）

- `Killer` 增加第二个 Event：`request_pause()` / `request_resume()` /
  `paused()`。与 `event`(kill) 互不干扰。
- **语义变更**：`Executor.check_window()` 失焦**不再 kill**，改为 `request_pause()`
  并返回 False；窗口回来时 `request_resume()` 并清空 `_warned_mismatch`
  （原 `_warned_focus` 改名）。只有"取不到窗口标题（非 Windows）"才 kill。
  取标题包了 try/except → 失败视为不匹配（暂停），比放行安全。
- `AutoTyper._wait_while_paused()`：暂停等待循环，每 0.05s 查一次，每 0.5s
  调 `_progress()` 让界面刷新。`run()` 主循环里加 `if self.kill.paused()`。
- `_sleep()`：仅当 `seconds >= 0.5` 时响应暂停（短到一次击键间隔的 sleep
  让它自然走完，免得状态机在半个动作中间被冻住）。从暂停恢复后
  **重置 deadline**，这段停顿重新计时。
- `_send(ch, urgent, mandatory)` 新增 `mandatory`：
  - `mandatory=False`（正常打字）：暂停就等恢复；**已 kill 则直接不发**。
  - `mandatory=True`（`_retype` 重打刚删掉的片段）：不发就会缺字，所以
    绕过暂停/停止检查，**必须补完**。`_emit_intended` 也加了同名参数并透传。
- `_h_pause_long` 记录 `pause_long_left`（墙钟剩余秒），`_sleep` 里递减，
  让界面能显示"长暂停中，剩 N 分钟"；`run()` 每轮记录 `cur_state`。
- `stats` 新增 `pause_count`；CLI summary 自动打印，GUI 输出行加 `pauses=`。
- GUI：新增「目标窗口标题（可选）」输入框（填了才有失焦暂停）、「⏸ 暂停/▶ 继续」
  按钮、`_tick()` 每 500ms 刷新状态栏（`STATE_LABELS` + 线性外推 ETA）。
  `pct` 消息不再直接写 status（交给 `_tick` 统一维护）。`_on_close` 取消
  `_tick_id`。`_window` 纳入 gui_settings.json 持久化。

### 验证

新增 4 项测试，sanity_check 共 **24 项全过**：

- `test_check_window_pauses_not_kills`：伪造 `ctypes.windll` 覆盖

四套测试全绿；CLI 端到端 `final_matches_source: True`。

### 两个真实 bug（都是测试逼出来的，我自己写的）

1. **`_send` 竞态**：主循环在迭代开头查 `paused()`，但暂停请求若落在
   一轮迭代中间，仍会多打一个字符。→ 在 `_send` 里加守卫。
2. **守卫写错导致缺字**：最初写 `if paused() and not killed()`，于是
   "既暂停又停止"时**穿透**，照发不误（buffer 400→401）。改成先判 killed 返回。
   但紧接着这个改法**打破了"已删未重打必须补完"这条不变式**
   （`test_kill_mid_edit_keeps_text` 立刻红）——于是才有了 `mandatory` 参数。
   **教训：`_send` 有"正常打字"与"重打已删片段"两种语义，不能一刀切。**
